# 疑難排解

[回到專案首頁](../README.md)

## 電腦聲音沒有錄到

1. 確認正在錄音，播放一段確定有聲音的影片或遊戲。
2. 在設定選擇**實際播放聲音的裝置**。Discord 指定耳機而 Windows 預設是螢幕喇叭時，跟隨 Windows 預設可能錄不到 Discord。
3. 將 Discord 與遊戲改成同一個播放裝置；目前第一版只錄一個播放裝置。
4. 檢查來源中斷提示；重新整理裝置後選擇可用裝置並套用。
5. 特殊獨占模式、驅動或受保護內容可能無法擷取，可先用一般播放器測試。

「目前安靜」只代表近期峰值很低；裝置已連接不等於存在可聽見的音訊。存檔後應試聽混音及電腦分軌。

## 麥克風沒有錄到／顯示 0x80070490

- 確認「同時錄製麥克風」已勾選並套用。
- 在 Windows 音效輸入設定確認裝置存在、未停用且音量有反應。
- 確認 Windows 允許桌面應用程式存取麥克風。
- 明確選擇要用的麥克風，避免預設裝置指向其他輸入。
- 開發機的 `0x80070490` 出現在找不到預設麥克風時，請先檢查裝置。

暫時只需要朋友與遊戲的聲音時，可以關閉麥克風錄製。直接從裝置擷取的麥克風不受 Discord 靜音、按鍵發話或降噪設定控制。

## 麥克風太大聲、混音破音或回音

- 降低設定中的電腦或麥克風混音音量。
- 比較兩份原始分軌；原始麥克風已破音時，需要調整 Windows 或硬體的輸入音量。
- 喇叭聲音可能再被麥克風收到，可改用耳機並檢查 Windows 麥克風監聽設定。
- 試聽剛儲存的音檔也會經過播放裝置，可能進入下一個片段。

## 快捷鍵沒有反應

- 檢查是否被占用，換一組包含 Ctrl 或 Alt 的組合後套用。
- 儲存與介面快捷鍵必須不同，F12 不開放使用。
- 編輯快捷鍵欄位時，全域快捷鍵暫停；離開欄位後恢復。
- 先在一般桌面測試，再確認遊戲或其他工具是否攔截按鍵。
- 也可從主畫面或系統匣右鍵選單操作。

## 關閉視窗後找不到程式

這是背景執行行為。按預設 `Ctrl + Alt + F10`，或從右下角系統匣（可能收在 `^` 中）雙擊圖示。要完全結束，使用系統匣的「結束 EchoReplay」。

## 開機沒有自動執行

1. 勾選「登入 Windows 時自動執行」並套用。
2. 若需要登入後錄音，也勾選「啟動程式後自動開始錄音」。
3. 開機啟動直接縮到系統匣，沒有視窗不代表沒啟動。
4. 移動 EXE 後，從新位置開啟，再按「套用設定」更新路徑。
5. 檢查 Windows 的啟動應用程式設定是否將 EchoReplay 停用。

目前尚未在開發環境實際重新登入驗證。

## 存檔失敗、找不到檔案或檔案較短

- 確認資料夾可寫入、磁碟空間足夠，外接磁碟或網路位置仍在線。
- 每次存檔建立新的 `Replay_…` 子資料夾，可用「查看音檔」開啟。
- 剛開始只錄了 30 秒時，即使設定 5 分鐘也只會保存已累積的 30 秒。
- 修改保留時間或來源後會重新累積；開始新的錄音也會清空原有緩衝。
- 存檔中不會啟動另一份匯出。輸出失敗後，近期緩衝持續更新，可修正路徑再存一次。
- 強制結束可能留下 `.partial` 暫存資料夾，其中檔案不代表已完整匯出。

## 回報問題

提供 Windows 版本、程式版本、播放／輸入裝置、重現步驟及錯誤訊息。`錄音資訊.json` 有時長、來源狀態與中斷計數，但不是完整除錯紀錄。

實機診斷指令見 [製作說明](DEVELOPMENT.md)。通常不需要附上包含聊天內容的原始錄音。
